# Benchmark protocol v2: three tracks, answers sealed

> **Why this exists.** A benchmark is only worth something if the agent can't see or remember the answer. Judges read rigor as a strength.
> v2 (2026-10-25) replaces v1's "rebuild pre-fix versions from snapshot.debian.org". The data showed too few recent human fixes (only 10 FTBR packages tagged since June 2026), and old-version archaeology would eat the week. See D-026.

## 1. The three tracks

| Track | Question | Needs builds? | Ground truth | Headline metric |
|---|---|---|---|---|
| **A: Diagnosis** | Does the agent name the right cause from Debian's published evidence? | No (no-build mode; `probe` disabled, see §3.4) | reproducible-notes tags (sealed) | tag@1, tag@3, family@1 on the post-cutoff test set |
| **B: Verified fix** | Can it produce a fix that is proven reproducible? | Yes | None needed: the twin build is the judge | Verified-fix rate, $/fix, minutes/fix |
| **C: Campaign** | Does one toolchain fix make a whole cluster reproducible? | Yes | Twin builds | Members verified / members |

## 2. Contamination boundary
- **Training cutoffs (model cards):**

  | Model | Pretraining data cutoff | Post-training cutoff |
  |---|---|---|
  | Ultra | Sep 2025 | May 2026 |
  | Super 3 | Jun 2025 | Feb 2026 |
  | Lightning | Sep 2025 | May 2026 |

- Post-training data is unlikely to include Debian notes, but web pretraining could include `packages.yml`, which is public on salsa.
- **Boundary: notes tagged on or after 2025-10-01 are "new"** (after every pretraining cutoff). Earlier tags are "old".
- We still run the memorization probe (§3.3), because the boundary isn't a guarantee.

## 3. Track A: dataset, run and scoring

### 3.1 Sets (built by `samebytes bench build --track A`)
- **test-new:**
  - unstable/amd64 FTBR packages with at least one tag **added after 2025-10-01** (tag-history diff, `DATA_SOURCES.md` §4).
  - Haskell items are capped at 10 (random, seed 26): 92 of the 136 are `haskell_abi_hash_differences`, which would dominate.
  - Expected size is about 54.
- **control-old:** 30 FTBR packages whose tags were all present before 2025-06-01, stratified by tag family, and disjoint from dev.
- **dev:** 15 old-tag packages disjoint from control. They are used freely to write prompts and rules.
- **Excluded from every sealed set:**
  - the flagship cluster and `hatchling` (the team knows the answer);
  - all Track B packages;
  - items whose only tags are uninformative (`*_requiring_further_investigation`, `*manually_added*`);
  - items whose evidence exceeds the cap (`DATA_SOURCES.md` §3);
  - items whose CI version differs from the version in `reproducible.json`.
- **Label noise:** notes often refer to an older version (only 40 of 574 FTBR notes match the current version). Keep these items, but report results separately for version-matched items.

### 3.2 Seal (before any test run)
1. `bench/answer_key/trackA_test.jsonl` holds `{"pkg","version","gt_tags":[…],"gt_families":[…],"set":"test-new|control-old"}`. It is generated by script from `packages.yml`; nobody needs to read it.
2. `sha256sum bench/answer_key/*.jsonl > bench/SEAL.txt`, then commit `SEAL.txt` **with the frozen prompts**. Record the commit hash in the run manifest.
3. The **family map** (`bench/families.yml`, a regex over tag names mapping to `timezone|time|locale|path|user_host|ordering|randomness|build_flags|toolchain_specific|other`) is written from the catalogue names **before** the seal, using dev items only.

### 3.3 Run
1. `SAMEBYTES_MODE=benchmark samebytes bench run --track A --set test-new,control-old --config ultra-agentic-nobuild`
2. Ablation configs, run on **test-new only** to control cost (`BUILD_PLAN.md` §6). **Scope (D-037):** only the first is planned; the others run only if Wednesday is ahead of schedule, and the README reports whichever ran.
   - `ultra-oneshot` (no tools): **planned.** It answers the track's key question, "do the tools matter?"
   - `super-agentic-nobuild`: optional (justifies Ultra as investigator)
   - `fast-oneshot` (Lightning or Nano): optional
   - `ultra-agentic-norules` (rule hints removed), on a fixed 20-item random subset (seed 26): optional
3. **Memorization probe:** `samebytes bench probe --track A` asks each model about every item *without evidence* (`AGENT_DESIGN.md` §5.5). An item is **flagged** for a model if the probe gets tag@3 right.
4. `samebytes bench score --track A` is the only code path that opens `answer_key/`.

### 3.4 No-build mode (Track A)
- Track A must not depend on 100+ env images.
- Tools that need an env image (`probe`, `which_package`, `search_source` with toolchain scope, `read_file sys:`) are **disabled**.
- The agent gets the digest, signals, CI log excerpts (`grep_build_log` on `ci1`/`ci2`), the catalogue, and source reading via a read-only unpacked source tree:
  - fetched with `dget` from the archive, **for the exact CI version**, before the run, with network on;
  - mounted offline during the run.
- So Track A measures *diagnosis from evidence plus source*. Track B measures the full agent.

### 3.5 Scoring
- **tag@1:** the first `issue_types` entry ∈ `gt_tags`. **tag@3:** any of the first 3 ∈ `gt_tags`.
- **family@1:** the family of the first predicted tag (or of `novel:*` via `varying_factor`) ∈ `gt_families`.
- **factor accuracy:** `varying_factor` agrees with the factor implied by the GT family (when the family implies one).
- **Cost and time:** sums from the ledger per item.
- **Report raw counts** (e.g. "31/54"), split into all items, items not flagged by the probe, and version-matched items, plus old vs new.

## 4. Track B: verified fix

- **Set:** `bench/trackB_candidates.txt` (`DATA_SOURCES.md` §7.2) after the baseline filter (T13). **Target 4 packages (D-037)**, chosen before the run for diversity of cause (not for expected success); add more only if the machine is idle. Report "n of 4" with every failure.
- **Mode:** `SAMEBYTES_MODE=benchmark`. Tavily, the BTS and sources.debian.org are off; builds and probes are offline. That's the headline run.
  - An optional second run in product mode shows what Tavily adds (only on failures, to save money).
- **Run once** with frozen config: `samebytes bench run --track B`.
- **Per package, report:**
  - status (`FIXED` / `FAILED` / `NOT_REPRODUCED` / `BASELINE_FTBFS`);
  - rounds, strategy class, patch size, grade (`ci-equivalent` / `ci-minus-time`);
  - $ and wall minutes;
  - failure reason.
- **Expert check (small n):** for FIXED items, one of you writes one line per item, "is this the fix you'd submit?" (yes / workaround / no), *after* the run. Publish it.

## 5. Track C: campaign
- Flagship cluster members (`FLAGSHIP_CASE.md` §2.4).
- **Metric:** members whose twin build is reproducible with the patched toolchain *and* not reproducible without it, out of members attempted.
- **Controls:** `crazy-complete` stays reproducible with the patched toolchain (no regression).

## 6. Leak paths and blocks (code-enforced where possible)

| # | Leak path | Block |
|---|---|---|
| L1 | `packages.yml` (package → cause) | Never loaded by agent code. `tests/test_no_answer_access.py` greps `src/samebytes/{agent,llm,digest,evidence,harness}` for `packages.yml` and `answer_key` and fails if found. The run-time file loader denylists `bench/answer_key/` and `**/packages.yml`. |
| L2 | rb-pkg and notes pages | The evidence fetcher has an allowlist of URL patterns (`dbdjson`, `dbdtxt`, `rbuild`, `logs`, `logdiffs`, `buildinfo`, `history`); anything else raises |
| L3 | Fixed source in the tree | Track A/B packages are *currently* FTBR (unfixed); we use the CI version. Nothing newer is fetched. |
| L4 | Web search | Tavily, BTS, tracker and sources.debian.org clients raise in benchmark mode |
| L5 | Network inside builds/probes | `--network none` / `networking.enabled=false`; the probe tool has no network |
| L6 | Model memory | Post-cutoff test set; memorization probe; old-vs-new comparison |
| L7 | Tuning on test | Dev set only; prompts frozen and hashed before the seal commit |
| L8 | Team knows answers | Flagship and Track B excluded from sealed sets; the answer key is script-generated and never opened before scoring |
| L9 | Answer strings in inputs | `leakguard` scans the **per-package user message** and every tool result for the item's GT tag names, bug numbers and note comments; a hit aborts the item (logged). The catalogue legitimately contains all tag names, so it is excluded from the scan, **and so are the `catalogue hints:` fields of RULE SIGNALS** (they are catalogue names chosen by the deterministic rules engine, not answer leakage; without this exclusion the guard would abort exactly the items where the rules point the right way). The scan runs on the message with those fields masked. |
| L10 | Cherry-picking | One run per config; any rerun is reported alongside the first |
| L11 | **The catalogue itself names the answer** (verified 2026-10-25: `timezone_variant_in_argparse_manpage`, description "argparse manpage >= 4.7 … vary on the timezone", on all 13 flagship packages) | The flagship is never a sealed item. Its headline run is **blind** (`--blind`: entries naming the tool are redacted from the system prompt, the rule hints and `catalogue_lookup`, recorded in the manifest; a blind leakguard checks for the label, the bug number and the description phrase; a no-tools memory probe is published next to it) and the product run is reported next to it (`AGENT_DESIGN.md` §3.1.1). For sealed Track A items the catalogue legitimately contains the true tag, as the public knowledge base the agent is meant to use; to show that this is not the whole result we also report `varying_factor` accuracy (factor/family@1), which doesn't need the label text. |

## 7. What the code must enforce (checklist, with tests)
- [ ] `SAMEBYTES_MODE=benchmark` makes the Tavily, BTS, tracker and sources clients raise `BenchmarkModeViolation`. Test: call each one in benchmark mode and expect the exception.
- [ ] File loader denylist plus `test_no_answer_access.py`.
- [ ] `leakguard` with a planted-leak unit test (inject a GT tag into a fake log and expect the item to abort).
- [ ] The run manifest holds the git commit, prompt hashes, model registry, SEAL hash, mode and date.
- [ ] The scorer is a separate CLI command that refuses to run if `predictions.jsonl` is newer than the manifest's freeze time plus the run end.
- [ ] Every model call is in the ledger; every build has an operation ID.

## 8. How we report it (README, site, video)
- **One table per track**, raw counts, ablation rows, and the probe-flagged split.
- **Method sentence:** "Answers were sealed (SHA-256 committed) before the run. The agent had no network, no access to Debian's notes, and no web search. Test items were tagged by Debian volunteers after the models' training cutoffs."
- **Prior work as context, not a head-to-head:**
  - RepLoc (ICSE 2018): file-level localization, 47.09% top-1 and 79.28% top-10 over 671 packages.
  - RepFix (ICSE 2022): 64/116 fixed.
  - EvidenT (ISSTA 2026): system-level package build repair, 53.88% on RISC-V.
  - Different tasks and datasets; say so.
- **Failure analysis:** the 3–5 most common failure reasons, with one example each.
